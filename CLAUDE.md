# Проект: хакатон Альфа-Банк × Changellenge — «AI-агент для разработки ML-моделей» (трек AutoML)

> Этот файл относится к ветке `feature/agent-models` (роль P4, владелец — @egrsid).
> Общий план команды (5 человек, роли, этапы, Git-процесс) живёт в `main`; здесь он сведён к тому, что нужно для работы над агентом.

## Суть проекта
Универсальный LLM-управляемый агент получает текстовое описание ML-задачи и CSV-файлы
(`train.csv`, `test.csv`, `data_dictionary.csv`, `sample_submission.csv`) и сам: анализирует данные, определяет тип задачи,
пишет и запускает код, обучает модель, валидирует, формирует файл предсказаний.
Сдаётся КОД агента (ZIP с `solution.py` в корне), а не модель. Платформа запускает его на разных задачах.

## Оценка
- Public: 2 известные задачи.
  1. Регрессия — годовое удельное энергопотребление зданий (`site_eui`), метрика RMSE. train 53 308 × 64, test 22 449 × 63.
  2. Мультикласс — тип кибератаки (`attack_cat`), основная метрика Macro F1. train 87 670 × 44, test 41 166 × 43.
- Private: 2 скрытые новые задачи (метрики и содержание не раскрыты). Берётся сабмит с лучшим public score, код не меняется.
- Баллы нормируются относительно бейзлайна (хуже или равно бейзлайну → 0):

$$S_{reg} = 100 \cdot \max\left(0,\; 1 - \frac{RMSE}{B_{RMSE}}\right), \qquad
S_{cls} = 100 \cdot \max\left(0,\; \frac{MacroF1 - B_{F1}}{1 - B_{F1}}\right)$$

$$Score = \frac{S_1 + S_2}{2}$$

Главное: надёжность и универсальность на НЕЗНАКОМЫХ задачах, а не подгонка под public.

## Подключение к LLM
- Модель: `qwen/qwen3.8-27b`. Протокол: OpenAI-совместимый (`{OPENAI_BASE_URL}/chat/completions`).
- Base URL (разработка): `https://changellenge.up.railway.app/v1`. Запасной для российских хостингов: `https://api.alfahack-gateway26.ru/v1`.
- API-ключ (`sk-...`) выдан команде. **Никогда не писать ключ в код, в `CLAUDE.md`, в коммиты, чаты и логи.**
  Локально хранить в `.env` (в `.gitignore`) или в переменных окружения.
- Лимит: 600 ₽ в день на ключ, бюджет общий на всю команду. При `Budget has been exceeded` ждать сброса в 3:00 МСК.
  Поэтому: тестовые вызовы короткие, логировать расход токенов, кэшировать ответы, не гонять LLM-цикл без нужды.
- **На платформе** адрес и ключ подставляются переменными `OPENAI_BASE_URL`, `OPENAI_API_KEY` (и опционально `OPENAI_MODEL`).
  Свои адрес и ключ в коде прописывать нельзя. Клиенты `openai`/`langchain-openai` читают переменные сами: `OpenAI()` без аргументов.
- После старта скрипта доступен только прокси: свой хост, прямой адрес модели и `pip install` из кода не работают.

```sh
export OPENAI_API_KEY="sk-..."          # подставить свой, не коммитить
export OPENAI_BASE_URL="https://changellenge.up.railway.app/v1"
```

## Формат сдачи и жёсткие ограничения
- ZIP до 100 МБ, **все файлы строго в корне архива, без папок**: `solution.py`, `requirements.txt`, корневые `.py`-модули.
  Модуль в подпапке при запуске недоступен → риск 0 баллов. Поэтому `agent.py`, `prompts_agent.py`, `memory.py` лежат плоско, рядом с `solution.py`.
- Запуск: `python3 solution.py task.md`; `submission.csv` — рядом с `task.md`. Формат — как в `sample_submission.csv`.
- Python 3.12; только библиотеки из `requirements.txt` (есть `openai`, `httpx`, `tenacity`, `pydantic`, `jsonschema`, `orjson`, `psutil`, `optuna`, `lightgbm`, `catboost`, `xgboost`, `pyarrow`). Сторонние пакеты и `.whl` добавлять нельзя.
- 8 CPU, 32 GB RAM, без GPU, без интернета, кроме прокси к LLM. 3 часа на задачу (включая LLM), потом процесс убивают и оценивают уже записанный `submission.csv`.
- Обучение только на данных кейса; предобученные модели нельзя. LLM — только Qwen через API организаторов.
- Сабмиты на платформу: 3 в день на команду — делает только P1.
- `baseline.py` организаторов использует `mcp` (в контейнере его нет): цикл «модель выбирает действие → скрипт выполняет» пишем на чистом `openai` + `subprocess`. Единственный инструмент в baseline — `run_python(code)`: новый процесс на вызов, файлы сохраняются, `env` почти пустой, cwd = каталог задачи.

# Ветка `feature/agent-models` — выбор модели, свой evaluator, пороги под F1, текст (P4)

> Ветка от `feature/agent-strategies` (`7ebe7a9`) ← `feature/experiment-memory` ← `feature/agent-loop`.
> Подробный план и итоги — `docs/plans/feature-agent-models.md`; предыдущие ветки — `docs/plans/feature-agent-*.md`.

## 1. Цель

1. **`model_search`** — вид гипотезы-стратегии: на признаках лучшего кода сравнить lightgbm / catboost / xgboost
   тем же evaluator, лучший — в обычное правило принятия; авто-запуск перед остановкой (сначала модель, потом `tune`).
2. **Свой evaluator** `agent_eval.py` (`LocalEvaluator`): агент работает и без `evaluator.py` P1 (P1 приоритетнее).
3. **Пороги под F1** `postprocess.py`: множители вероятностей классов на OOF, честная оценка по частям OOF.
4. **Текст:** TF-IDF + SVD в `BASE_CODE` для текстовых колонок (предобученные эмбеддинги запрещены правилами).

Не входит: другие семейства моделей (контракт evaluator с P1 — только 3 бустинга), AutoML-библиотеки (зона P1/P3),
семантическая разметка категорий через Qwen.

## 2. Шаги (порядок не перескакивать, каждый — отдельный коммит)

0. План (`docs/plans/feature-agent-models.md`) и этот раздел.
1. `agent_eval.py` + проводка в `research()` + тесты (`StubEvaluator` в моках — подкласс `LocalEvaluator`).
2. `model_search` + перенос параметров + авто-порядок `model_search → tune` + тесты.
3. `postprocess.py` + финальный шаг исследования + тесты.
4. TF-IDF + эвристика текстовых колонок + строка в промптах + синтетика + тесты.
5. Замеры (dry-run обеих задач на своём evaluator), статус.

## 3. Как проверять

```sh
LLM_DISABLED=1 .venv/bin/python -m pytest tests/ -q
.venv/bin/python tools/try_agent.py "Многоклассовая классификация/task.md" --dry-run
```

## 4. Definition of Done

- Прежние тесты зелёные; новые стратегии выключаются флагами `AgentConfig`.
- Без `evaluator.py` P1 агент работает на `LocalEvaluator` и не трогает `submission.csv`; `local_evaluator=False` → `[]`.
- Новые модули плоские, импортируются без модулей команды (sklearn/бустинги — внутри функций).
- Промпт планировщика ≤ 4k токенов.

## 5. Риски

| Риск | Мера |
|---|---|
| `model_search` съедает окно research | бюджет `min(seconds, share · остаток)`, пропуск модели по оценке времени, дедлайн между фолдами |
| Пороги переобучаются под OOF | подбор на K−1 частях OOF, проверка на оставшейся, тот же порог шума |
| Свой evaluator расходится с P1 | P1 приоритетнее, контракт тот же |

- Любой вызов LLM: таймаут, ограниченное число ретраев, логирование токенов, аккуратная обработка `Budget has been exceeded`.
  Модель `qwen/qwen3.8-27b` всегда рассуждает; отключается `extra_body={"reasoning": {"enabled": false}}` (агент уже передаёт).
- Код, сгенерированный LLM, исполняется в отдельном процессе с таймаутом; его выводу не доверяем без проверки харнессом.
- Ничего не скачивать из интернета и не вызывать `pip` из кода. Абсолютные пути к своей машине в код не писать.
- Файлы других владельцев правим только через PR к ним/с их согласия. `solution.py` и `schemas.py` — только P1.
- Не коммитить: `.env`, ключи, данные (`*.csv`), `*.zip`, `.venv`, `.llm_cache/`, `.agent_work/`.
