# Отчёт: как агент стал улучшать основу (ветки `feature/agent-honest-compare` → … → `feature/agent-tools`)

> P4, @egrsid, 2026-10-25. Сводка для PR и для команды: что и зачем сделано, как проверить, что измерено, что осталось.
> Планы по веткам — рядом (`feature-agent-*.md`); здесь — общая картина.

## 1. Исходная проблема

Сабмит v2 (`main`, 22.46 балла) вырос с 15 за счёт fallback P3; агент в файл ничего не записывал. Разбор показал семь
причин: дорогая оценка гипотезы (2–5 мин), шум сравнения ≈ размеру выигрыша, LLM не знала, что уже делает fallback,
нечестное сравнение (веса бленда fallback подобраны на тех же OOF, претенденты оценивались честно; 1 сид против 3),
выбрасывание не принятых кандидатов, AutoML на 40 мин (проигрывал), риск переобучения под CV. Главное же —
**узкое пространство действий**: в режиме рецепта агент мог только добавлять колонки, а всё, что двигало score
(схема CV, признаки сущности, исключения, веса), было ему недоступно.

## 2. Что сделано (по веткам, каждая — в своём `docs/plans/feature-agent-*.md`)

| Ветка | Суть | Ключевые файлы |
|---|---|---|
| `agent-honest-compare` | честная оценка бленда fallback (`fold_weights`, `honest_view`); агент доводит лучшего до 3 сидов (`bag`); сравнение с обеих сторон честное; AutoML выкл. | `fallback.py`, `agent_eval.py`, `agent.py`, `solution.py` |
| `agent-screening` | скрининг одной LightGBM (20–70 с вместо 2–5 мин); `early_stopping=0`; агент работает всё окно (лимиты итераций снижены); повтор пустых планов | `agent_eval.ScreenEvaluator`, `fallback.cv_model`, `agent.py` |
| `agent-signals` | `recipe_signals` (что делает baseline, важности, дрейф train→test); фильтр бесполезных колонок | `agent_eval.py`, `agent.py`, `prompts_agent.py` |
| `agent-holdout` | скрытый фолд, растущий порог, доля выигранных фолдов, итоговая проверка | `agent.py`, `agent_eval.holdout_fold` |
| `agent-pool` | пул не принятых кандидатов → только в бленд; объединение «почти принятых» | `agent.py`, `solution.improve` |
| `agent-tools` | **действия над рецептом**: `drop`, `weights` (dedup/recency/class), `target_stats`; «быстрый рецепт» (заморозка медленных членов); скрининг больших задач (подвыборка); подсказки харнесса (`suggested_tools`) | `agent.py`, `agent_eval.py`, `fallback.py`, `prompts_agent.py` |

Дополнительно: дубли гипотез по семейству видов (`memory.same_idea`), сброс заметок фильтра между экспериментами,
резерв времени на доводку (`_stop_reason`), `screen_k = 0.25`.

## 3. Что измерено

**Оценка бленда fallback завышена** (веса на тех же OOF): регрессия RMSE 40.52 против 41.09 честно (SE 0.21),
мультикласс Macro F1 0.650 против 0.645. На отложенных копиях (P3: год 5 / 25% групп дублей) честный бленд `ensemble`
не хуже записанного fallback (30.25 против 30.31 RMSE; 0.6445 против 0.6398 F1).

**Скорость агента (public-мультикласс, 87 тыс. строк):** эталон рецепта 910 → 329 с; скрининг 148/312 → 64/70–150 с.
Регрессия: гипотез за ~27 мин 11 (раньше 3 за 10 мин), скрининг 20–50 с.

**Живые прогоны Qwen:**
- регрессия: принята «средняя площадь по типу здания» (+0.63 RMSE, 4/4 фолда), **скрытый фолд (год 5) отклонил её
  (−1.46)** — в файле fallback; защита сработала;
- мультикласс: принята `target_stats` «среднее sbytes по service» (+0.0035 F1, 3/4 фолда); скрытый фолд не успел;
  остальные 8 гипотез отклонены (колонки на скрининге хуже на 0.0006–0.016);
- ZIP `ba2eb64` на 6 синтетических задачах (`run_all --llm`): 6/6 корректный файл; `multi_imbalance` — агент принят,
  скрытый фолд пройден (0.849 против 0.822), доводка до 3 сидов, на ответах test **0.845 против 0.824** без LLM.
- расход LLM: ~45 тыс. токенов на прогон; за сутки потрачено < 2% лимита.

## 4. Как проверить

```sh
LLM_DISABLED=1 .venv/bin/python -m pytest tests/ -q                                 # юнит-тесты, MockLLM
.venv/bin/python tools/make_zip.py                                                  # dist/solution_<коммит>.zip
set -a; source .env; set +a                                                         # живой Qwen (ключ не печатать)
.venv/bin/python tools/try_solution.py "Регрессия/task.md" --iters 100 --minutes 60
.venv/bin/python tools/run_all.py dist/solution_<коммит>.zip --llm --only multi_imbalance,bin_f1_str
```

Отложенные копии public-задач и скрипты замеров — вне репозитория (scratchpad сессии); логика описана в
`feature-agent-honest-compare.md`.

## 5. Известные ограничения и риски

- На платформе (8 CPU) агент использует окно до T+2ч30 и доводку до T+2ч50 (`RESEARCH_END`, `final_reserve_seconds`):
  полный 3-часовой прогон на платформенном железе не делался.
- Агент пока не нашёл улучшений на public-регрессии, прошедших скрытый фолд; в файле там fallback. Выигрыш на
  синтетике (`multi_imbalance`) — одна точка; на public-мультиклассе скрытый фолд для принятой гипотезы не проверен.
- Скрытый фолд — одна шумная проверка: настоящее маленькое улучшение может не пройти (сознательно).
- Скрининг сравнивает одну модель, итог — бленд: колонка, полезная только XGBoost/RandomForest, может быть отсеяна.
- Не сделано: банк признаков, `DROP` по LLM-коду, члены бленда под дисбаланс (зона P3), AutoML как действие агента.
- Правки в `fallback.py` (P3) и `solution.py` (P1) сделаны с согласия владельцев; в PR к ним — отдельные коммиты.
