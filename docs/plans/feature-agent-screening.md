# Ветка `feature/agent-screening` — быстрый скрининг гипотез агента (P4, @egrsid; правка P3 — с согласия)

> Идея 2 из разбора «почему агент не улучшает модель». Ветка от `feature/agent-honest-compare` (идея 1): скрининг
> опирается на `RecipeEvaluator` оттуда.

## 1. Зачем

Живой прогон на public-регрессии: 3 гипотезы за 10 минут, все отклонены. Две причины:
- **Оценка гипотезы дорогая**: `RecipeEvaluator` переобучает все члены бленда fallback (LGBM + XGB + RF × 5 фолдов),
  114–318 с на гипотезу → за окно агента ~20–30 гипотез.
- **Шум сравнения ≈ размеру выигрыша**: новая колонка меняет обучение деревьев почти как смена сида (одиночный сид
  «гуляет» на ±0.5 RMSE при пороге принятия 0.4–0.6), плюс выбор итерации ранней остановкой по валидации.

И третья, найденная по ходу: **агент останавливался задолго до конца окна** — `max_iters=12` и плато после 5
неудач подряд (`max_no_improve=5`): на платформе ~2 ч окна, а агент уходил через 15–25 мин.

## 2. Что сделано

| Что | Где |
|---|---|
| `cv_model(..., early_stopping=0)` / `_fit_predict`: обучение ровно `n_estimators` деревьев без ранней остановки (LightGBM, XGBoost, CatBoost); по умолчанию — как раньше | `fallback.py` |
| `ScreenEvaluator`: один LightGBM рецепта (самый весомый; иначе лучший LightGBM fallback) на тех же матрицах, фолдах, признаках сущности и исключениях; фиксированное число деревьев = медиана итераций этого LightGBM у fallback; 2 сида с общими случайными числами (одни и те же у эталона и кандидата), OOF усреднён | `agent_eval.py` |
| агент в режиме рецепта: эталон скрининга — признаки текущего лучшего кода (пересчёт при принятии); гипотеза сначала скринится, полная оценка — только если выигрыш скрининга > `screen_k` · шум парных разностей (по умолчанию 0); отсеянная — «rejected» без ремонта кода, выигрыш скрининга — в памяти экспериментов (LLM его видит) | `agent.py` |
| пороги остановки: `max_iters` 12 → 100, `max_no_improve` 5 → 30, `max_consecutive_failures` 3 → 6, `max_tokens` 120 тыс. → 600 тыс.: агента ограничивает окно research | `agent.py` (`AgentConfig`) |

```sh
set -a; source .env; set +a                                               # живой прогон на Qwen

```

Тесты (`tests/test_agent_screen.py`): фиксированное число деревьев; скрининг детерминирован и видит полезную колонку;
отсеянная гипотеза не оценивается рецептом и не чинится; полезная проходит в полную оценку и принимается; скрининг
выключается.

## 5. Ограничения

- Скрининг сравнивает одну модель, а итог — бленд: колонка, полезная только XGBoost или RandomForest, может быть
  отсеяна. Порог по умолчанию мягкий (любой положительный выигрыш).
- Метрики по меткам скринятся по argmax, без порога/весов классов.
