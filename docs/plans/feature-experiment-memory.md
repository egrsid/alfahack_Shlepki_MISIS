# План ветки `feature/experiment-memory` (P4, @egrsid)

> Копия плана из `CLAUDE.md` ветки. Ниже, в разделе «Статус выполнения», — что сделано, как проверить и известные ограничения.

## 1. Цель и границы

**Цель ветки:** превратить минимальный журнал `memory.py` в память, которая на 12–30 итерациях даёт планировщику и
кодеру **сжатую и полезную** картину: что сработало и почему, какие направления исчерпаны, что ещё не трогали,
какие гипотезы — дубли уже проверенных. Критерий успеха — меньше повторов и пустых итераций при том же лимите промпта.

**Входит в ветку:**
- `memory.py` — сжатие сводки, дедупликация гипотез, «что ещё не пробовали», дифф кода, восстановление из JSONL.
- Минимальная проводка в `agent.py` (точки перечислены в разделе 4) и, при необходимости, заголовки секций в `prompts_agent.py`.
- Тесты: `tests/test_agent_memory.py` (+ существующие тесты цикла должны остаться зелёными).
- `docs/plans/feature-experiment-memory.md` — первым коммитом.

**Не входит:** логика цикла, правило принятия, раннер, промпты ролей по существу (это `agent-loop`, менять только
по необходимости и точечно); optuna и анализ худших объектов (`feature/agent-strategies`); чужие модули P1/P2/P3/P5.

**Ограничения:** только stdlib + numpy/pandas (никаких эмбеддингов и внешних моделей — нет интернета и GPU,
LLM-вызовы на память не тратим); `memory.py` по-прежнему импортируется без остальных модулей команды.

## 2. Что есть сейчас (минимальная версия из `agent-loop`)

- `Experiment(id, hypothesis, kind, status, cv_score, cv_std, gain, code_hash, error, duration_s, tokens_in/out, ts)`.
- `ExperimentMemory`: `add`, `add_note` (заметки критика, последние 3), `next_id`, `tried_titles`, `tried_kinds`,
  `find_code(hash)`, `summary(max_chars, recent=8)`, `dump_jsonl(path)`.
- `code_hash` (без пустых строк/хвостовых пробелов), `normalize_title` (нижний регистр, без пунктуации).

Слабые места:
- `summary` при переполнении просто выбрасывает старые эксперименты — теряется, что сработало в начале.
- Дубли ловятся только по точному совпадению нормализованного названия
  («Frequency encoding of facility_type» ≠ «Count encoding facility_type»).
- Нет картины покрытия: какие `kind`/колонки не трогали, какие направления исчерпаны.
- Кодер и планировщик видят только итоговый код лучшего, но не *что именно* изменилось в принятых шагах.

## 3. Контракт (обратная совместимость обязательна)

Все существующие методы и сигнатуры остаются, `agent.py` из `agent-loop` работает без изменений.
Новое — только добавлением:

```python
@dataclass
class Experiment:            # + поля со значениями по умолчанию
    ...
    columns: list[str] = []   # исходные колонки, которых касается изменение
    diff: str = ""            # сжатый дифф кода относительно базы (только +/- строки, ≤ ~15 строк)
    base_hash: str = ""       # code_hash базы, от которой сделан эксперимент

code_diff(old: str, new: str, max_lines: int = 15) -> str      # 0 — без обрезки; при обрезке важнее «+»
columns_in(code: str, known: Iterable[str]) -> list[str]      # строковые литералы, совпадающие с колонками
title_tokens(title) -> set[str]                                # смысловые слова: без стоп-слов, синонимы
mentioned_columns(text, known) -> set[str]                     # колонки, названные в тексте целым словом
similar_titles(a: str, b: str) -> float                        # 0..1, среднее Жаккара и перекрытия
same_idea(title_a, kind_a, title_b, kind_b, columns=(), threshold=0.6) -> bool   # правило раздела 6

ExperimentMemory(columns=())                  # колонки задачи (агент заполняет в _prepare)
    same_idea(...), find_similar(title, kind, threshold=0.6) -> Experiment | None
    kind_stats() -> list[str]                 # итог по видам
    coverage(all_columns=None, kinds=(), task_type="") -> dict   # untried_kinds, exhausted_kinds,
                                              #   untouched_columns, n_untouched_columns
    planner_brief(max_chars, all_columns=None, kinds=(), task_type="") -> str   # summary + покрытие
    summary(max_chars, recent=8) -> str       # та же сигнатура, новое сжатие (раздел 5)
    load_jsonl(path, columns=()) -> ExperimentMemory   # classmethod, обратный dump_jsonl
```

## 4. Проводка в `agent.py` (минимальные точки)

1. `_iterate` → при записи `Experiment` заполнять `columns`, `diff`, `base_hash` (код базы и колонки уже есть в цикле).
   Колонки — литералы в диффе плюс целые группы `spec`, если дифф обращается к `"cat_cols"`/`"date_cols"`/`"text_cols"`.
2. `normalize_hypotheses` → дубли по `memory.find_similar`, а не только по точному названию (через параметр, по умолчанию — старое поведение).
3. `_plan` → `memory.planner_brief(...)` вместо `memory.summary(...)`, если метод есть.
4. `_write_code` → в сводку для кодера — диффы принятых шагов («что уже дало выигрыш»): `summary(coder_memory_chars, recent=4)`.

Каждая точка — отдельный маленький коммит; тесты цикла (`tests/test_agent_loop.py`) обязаны оставаться зелёными.

## 5. Сжатие сводки (`summary`)

Секции по приоритету; при нехватке места режется низший приоритет (порядок резки: заметки → «не повторять» →
последние, кроме самого свежего → диффы принятых → итог по видам), принятые шаги и самый свежий эксперимент не режутся:
1. **Принятые шаги** — всегда целиком: `#id kind | title | gain | дифф (≤ 3 строки)`.
2. **Итог по kind** — одна строка на вид: `features: 6 tried, 1 accepted (best gain +0.024), 3 rejected, 2 failed (timeout)`;
   только когда экспериментов больше, чем `recent`.
3. **Последние N** экспериментов подробно (как сейчас).
4. **Не повторять** — короткие названия отклонённых/упавших одной строкой.
5. **Заметки критика.**

Инвариант: `len(summary(max_chars)) <= max_chars` для любого числа экспериментов; на 30 экспериментах при
`max_chars=1500` в сводке есть все принятые и все виды.

## 6. Дедупликация гипотез

- Токены названия: нижний регистр, без пунктуации и стоп-слов (`of, the, for, add, create, feature(s), column(s)…`),
  простая нормализация форм (`encoding/encode/encoded`), словарь синонимов (`frequency≈count`, `ratio≈divide`,
  `interaction≈product`, `log≈log1p`, `nan≈missing`).
- Дубль только при совпадающем `kind`. Если в обоих названиях есть колонки задачи: разные наборы → не дубль;
  одинаковые → сравниваются «действия» (слова без имён колонок). Без колонок — сходство всего названия ≥ `threshold`.
  Противоположные действия (`increase`/`decrease`) — никогда не дубль.
  (Исходное правило «совпали `kind` и колонки → дубль» отброшено: `sbytes/dbytes` и `sbytes − dbytes` — разные идеи.)
- Проверка идёт против памяти, очереди и гипотез выше в том же плане.
- Повтор *отклонённой* гипотезы — отсекается; повтор *упавшей* — разрешён один раз (могла упасть из-за кода, а не идеи).
- Порог калибруется табличным тестом на парах «дубль / не дубль» (≥ 20 пар, включая реальные названия из живых прогонов).

## 7. Покрытие («что ещё не пробовали»)

- `untried_kinds` — виды из `prompts_agent.KINDS`, которых не было (с учётом типа задачи: `target_transform` только для регрессии).
- `exhausted_kinds` — ≥ 3 попыток без принятия → планировщику «не предлагать, если нет новой идеи».
- `untouched_columns` — исходные колонки, не встречавшиеся ни в одном `columns` (не более ~15 имён, приоритет — из
  профиля, если передан порядок важности, иначе по порядку колонок).

## 8. План работ по шагам (порядок не перескакивать)

Каждый шаг — отдельный маленький коммит (`feat|fix|test|docs|refactor: что сделано`).

0. `docs/plans/feature-experiment-memory.md` — первым коммитом (копия разделов 1–9 этого блока).
1. Новые поля `Experiment` + `load_jsonl` (round-trip со старым и новым форматом JSONL) + тесты.
2. `code_diff`, `columns_in` + тесты (переименования, пустой дифф, длинный дифф обрезается).
3. `similar_titles`, `find_similar` + табличные тесты на пары дубль/не дубль.
4. Новое сжатие `summary` по приоритетам + тесты на инвариант длины и сохранение принятых.
5. `coverage`, `planner_brief` + тесты.
6. Проводка в `agent.py` по точкам раздела 4 (по коммиту на точку) + интеграционный тест на моках:
   планировщик повторно предлагает перефразированную отклонённую гипотезу → она не исполняется.
7. Замер: размер промптов planner/coder на 12 и 30 синтетических экспериментах (`tests/test_agent_prompts.py`),
   dry-run `tools/try_agent.py` на обеих public-задачах. Живой прогон Qwen — только если меняются промпты, ≤ 3 итераций.
8. PR в `main` после мержа `agent-loop` (раздел 10).

### Известные ограничения

- Синонимы и стоп-слова — ручной английский словарь. Если Qwen назовёт гипотезу по-русски, дубли ловятся только
  точным совпадением названия.
- Колонка в названии гипотезы распознаётся только по имени (`floor_area` или `floor area`): «возраст здания» не
  связывается с `year_built`. Из кода колонки берутся по строковым литералам и группам `spec`; f-строки и имена,
  собранные в рантайме, не видны.
- Противоположные действия заданы только парой `increase`/`decrease`.
- Живой прогон с Qwen не делался: промпты ролей не менялись (по плану — не нужен). Эффект «меньше повторов» на реальной
  модели не измерен — проверить на ближайшем живом прогоне (`--iters 6`, чтобы сработал re-plan).
- `load_jsonl` агентом пока не используется (отладка; пригодится для возобновления после сбоя).
