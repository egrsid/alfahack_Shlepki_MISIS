# План ветки `feature/fallback-pipeline` (P3, ML-ядро)

> Ветка создана от `feature/metrics-submission` (нужны `metrics.py` и `submission.py`); мержится в `main` после неё.

## 1. Цель и границы

**Цель:** `fallback.run(spec, deadline) -> Candidate` — детерминированный пайплайн без LLM, который на любой
табличной задаче за ~15 мин (8 CPU / 32 ГБ) даёт честный CV и пишет `submission.csv` СРАЗУ после первой модели,
перезаписывая его только при улучшении CV. Это страховка от падения LLM, агента и от лимита времени,
и одновременно стартовый `best` для агента P4.

**Входит:** `preprocess.py` (авто-предобработка), `fallback.py` (CV, модели, бленд, запись), тесты.
**Не входит:** `solution.py` (P1 — интеграция), понимание задачи (P2), харнесс `evaluator.py` (P1; когда смержится,
fallback переходит на его сплиты).

## 2. Контракты

```python
fallback.run(spec: TaskSpec, deadline: Deadline | None = None, config: FallbackConfig | None = None) -> Candidate
fallback.guess_spec(task_dir) -> TaskSpec-подобный объект   # эвристики на случай, если understand_task упал
preprocess.prepare(train_x, test_x, spec) -> Prepared(X, X_test, cat_cols, high_card, report)
preprocess.model_frame(prep, X, model) -> (frame, cat_features)    # адаптер под lightgbm / xgboost / catboost
```

`Candidate` (как в `schemas.py` из плана P1): `oof`/`test_pred` в «сырых» единицах (вероятности `(n, k)` по
`meta["classes"]`), `cv_score`/`cv_std` — без пост-обработки (argmax), чтобы сравнение с кандидатами агента было честным.
`meta`: `fold_scores`, `folds` (id фолда для каждой строки train), `model`, `params`, `target_transform`, `n_splits`,
`seed`, `classes`, `decision` (порог/веса классов), `cv_score_post` (CV с decision, кросс-оценка), `members`
(для бленда), `preprocess` (отчёт), `seconds`.

## 3. Шаги
1. `preprocess.py`: типы колонок (число, категория, дата, текст, числа-строками), удаление константных,
   id-подобных, дублирующих колонок и колонок, пустых в test; категории — редкие → `__rare__`, частотное кодирование,
   высокая кардинальность; даты → год/месяц/день/день недели/час/timestamp; текст → длины + TF-IDF→SVD;
   подсказки из `spec.cat_cols/date_cols/text_cols/drop_cols`.
2. `fallback.py`: K-fold (stratified для классификации, сид 42, как у заглушки evaluator P4), LightGBM → CatBoost →
   XGBoost с ранней остановкой и лимитом времени на фолд (колбэки), лог-таргет для регрессии по CV,
   `class_weight=balanced`-вариант для F1-подобных метрик при дисбалансе, жадный бленд (Caruana) по OOF,
   порог/веса классов (`metrics.crossfit_decision`), запись через `submission.write` только при улучшении.
3. Устойчивость: константный сабмит в первые секунды; сбой одной модели не роняет остальные; если не обучилась ни одна —
   кандидат-константа; никакой сети/LLM.
4. Тесты на синтетике (регрессия, бинарная, мультикласс со строковыми метками, пропуски, даты, текст) и замер времени
   на прокси размера public-задач.

## 4. Критерии готовности
- Работает на обеих public-задачах и на синтетике другого типа; укладывается в бюджет (по умолчанию 900 с).
- `submission.csv` валиден после первой модели; при падении любого этапа остаётся лучший записанный.
- Заметно лучше `solution.py` v0 (LightGBM без CV) по CV.

## 5. Риски
- Нет локально данных public-задач → прокси-датасеты того же размера; финальная проверка — когда P1 соберёт `solution.py`.
- CatBoost на мультиклассе медленный → оценка времени по LightGBM, пропуск при нехватке, лимит на фолд.
- Порог/веса классов переобучаются на OOF → берутся только если выигрыш подтверждён на других фолдах.

## Статус выполнения

**Сделано**
- `preprocess.py`: типы колонок (число, числа-строками вида «12,5», дата, текст, категория) с подсказками
  `spec.cat_cols/date_cols/text_cols/drop_cols`; удаление констант, id-подобных колонок, уникальных строк (uuid),
  дублей, колонок, пустых в test; категории — редкие и невиданные в train уровни → `__rare__`, частотный признак,
  высокая кардинальность → коды по частоте для LightGBM/XGBoost; даты → год/месяц/день/день недели/день года/час/timestamp;
  текст → длины + TF-IDF→SVD; безопасные имена колонок (LightGBM/XGBoost падают на `[ ] { } : , "`), отчёт `report`.
- `fallback.py`: константный сабмит в первые секунды → схема CV по данным (см. ниже) → LightGBM →
  [без колонки-периода, если test — новый период] → [LightGBM на log1p, если таргет скошен] →
  [LightGBM `class_weight=balanced` для F1-подобных метрик при дисбалансе ≥ 5:1] → XGBoost → CatBoost (последним,
  с потолком 4 × время первого LightGBM) → жадный бленд (Caruana, принимается только с выигрышем больше шума по
  фолдам) → порог/веса классов (принимаются, только если выигрыш подтверждён на чужих фолдах). Ранняя остановка,
  лимит времени на фолд колбэками всех трёх библиотек, пропуск модели, если по оценке не успевает. Классы, которых нет
  в обучении фолда, обрабатываются (XGBoost иначе падает). Сбой модели не роняет остальные; если не обучилась ни
  одна — кандидат-константа. Потоки — с учётом cgroup/affinity и размера данных, `FALLBACK_THREADS` — вручную.
- Схема CV `choose_cv` (в `meta["cv_scheme"]`, фолды — в `meta["folds"]`, чтобы P1/P4 могли переиспользовать):
  `period` — в test только новые значения целочисленной колонки-кода (train 1..5, test 6) или даты позже train →
  фолды по периодам; `duplicates` — в train ≥ 5% строк с дублями, а у test близнецов в train вдвое меньше →
  одинаковые строки в одном фолде (`StratifiedGroupKFold`); иначе `random` — (Stratified)KFold, seed 42.
- Сдвиг пропорций классов train → test: EM-оценка (Saerens 2002) по первой калиброванной модели —
  в `meta["label_shift"]` как диагностика; коррекция весов классов — опция `label_shift=True`, по умолчанию выключена
  (см. замеры).
- Выбор лучшего и перезапись `submission.csv` — по CV того, что реально уходит в файл (`meta["cv_score_post"]`);
  `cv_score` — без пост-обработки, для честного сравнения с кандидатами агента.
- `guess_spec(task_dir)` — минимальные эвристики (id/таргет из образца, метрика из `task.md`, тип по таргету) для
  автономного запуска `python3 fallback.py task.md` и как запасной вариант, если `understand_task` упал.
  Это не замена модулю P2: при наличии `TaskSpec` от P2 fallback берёт его, проверяя только явные противоречия
  (дробный таргет при классификации, нечисловой при регрессии, метрика не того типа).

**Как проверить**
```sh
.venv/bin/python -m pytest tests/ -q        # 87 тестов, ~10 с
python3 fallback.py путь/к/task.md          # автономный прогон, пишет submission.csv рядом с task.md
```

**Замеры**
- Titanic (реальные данные; 650 train / 241 отложено, 5 случайных разбиений), accuracy на отложенной части:
  v0 `solution.py` — 0.797, fallback — 0.812 (лучше в 4 из 5 разбиений); CV fallback 0.833 (оптимизм ~2 п.п.
  от выбора лучшей из моделей на маленьких данных).
- Потоки (Mac, одинаковый CV): 3 000 строк — 1 поток 1 с, 15 потоков 25 с; 87 670 строк × 10 классов — 2/4/8 потоков
  184/152/202 с; 53 308 строк — 13/11/16 с → LightGBM/XGBoost: не больше половины ядер (≈ физические) и «строк / 10 000»;
  на платформе (8 CPU) это 4 потока. CatBoost — все ядра. Стоит перемерить в Docker (`feature/docker-check`, P5).
- Прокси public-задач (синтетика той же формы: 53 308×64 регрессия со скошенным таргетом и пропусками; 87 670×44,
  10 классов с дисбалансом 600:1 и категорией на 130 уровней), 8 потоков, бюджет 900 с:

  | прокси | время | LightGBM | log1p | CatBoost | LGBM balanced | XGBoost | итог |
  |---|---|---|---|---|---|---|---|
  | регрессия, RMSE | 23 с | 69.80 | 71.11 | **69.29** | — | 69.92 | CatBoost |
  | мультикласс, macro F1 | 605 с | 0.740 | — | 0.747 (упёрся в лимит 386 с) | **0.786** | 0.744 | CatBoost + веса классов: **0.814** |

  Веса классов под macro F1 (кросс-оценка на чужих фолдах) дают +0.06…0.07; balanced-вариант +0.046 к сырому CV.
  Сабмит после первой модели — через ~70 с; `check_file` — ок. Качество на прокси ничего не говорит о public score.

**Public-данные (итерация 2)** — 8 потоков, бюджет 900 с, `python3 fallback.py task.md` на копиях задач.

Что нашлось в данных и что с этим сделано:
- Регрессия: в train `Year_Factor` 1–5, в test только 6; 38% зданий test встречаются в train в другие годы.
  Случайный K-fold смешивает годы и одни и те же здания → CV оптимистичен (RMSE 40.7). Теперь фолды по годам
  (честный «новый год»): RMSE 43.3. По этому CV код года мешает (LightGBM 45.13 → 44.72 без него) — исключается.
- Мультикласс: в train 45% строк имеют дубли (`Analysis`/`DoS`/`Backdoor` ~80%, `Generic` 96%), а у test близнецы
  в train только у 8.6% строк (test — официальный hold-out UNSW-NB15). Случайный K-fold мерил запоминание дублей
  и подбирал под него веса классов. Теперь дубли в одном фолде.
- CatBoost на обеих задачах худший (RMSE 46.3; Macro F1 0.557) и на мультиклассе съедал 65% бюджета. Ускорен
  (`border_count=128`, `max_ctr_complexity=1`, Bernoulli 0.8, `one_hot_max_size=16`: фолд 69.6 → 18.1 с при logloss
  0.4786 → 0.4751), перенесён в конец очереди и ограничен 4 × время первого LightGBM.
- Бленд: отбор по logloss проверен и отвергнут (отбрасывал balanced-модель, бленд 0.591); отбор по метрике задачи +
  принятие только при выигрыше больше SE парных разностей по фолдам.
- Сдвиг пропорций классов: EM даёт для test `DoS` 0.0% (в train 7%), `Backdoor` 6.1% (1%) — неправдоподобно.
  Проверка на реальном OOF (часть фолдов пересэмплирована к известным пропорциям): коррекция ухудшила Macro F1 во
  всех 5 сценариях (−0.004…−0.059), а без сдвига EM находил ложный (TV 0.04). Поэтому выключена по умолчанию.
  Обычные веса классов в тех же сценариях: +0.03…+0.05 к argmax.
- Второй пресет LightGBM (глубже, lr 0.03, сильная регуляризация) проверен и не взят: хуже на обеих задачах.

| задача | версия | схема CV | время | модели (CV) | итог |

| регрессия, RMSE ↓ | v1 | random | 149 с | LGBM 41.73, log 42.91, CatBoost 42.22, XGB 40.68 | XGB 40.68 (оптимистично) |
| регрессия, RMSE ↓ | v4 | по годам | 147 с | LGBM 45.13 → без года 44.72, log 47.88, XGB 43.48, CatBoost 46.28 | бленд XGB+LGBM **43.29** |
| мультикласс, Macro F1 ↑ | v1 | random | 558 с | LGBM 0.608, CatBoost 0.527 (397 с), balanced 0.601, XGB 0.610 | бленд + веса 0.650 (завышен дублями) |
| мультикласс, Macro F1 ↑ | v4 | группы дублей | 420 с | LGBM 0.604, balanced 0.622, XGB 0.611, CatBoost 0.557 (209 с, потолок) | бленд balanced+XGB + веса **0.649** |

v4 — финальный код ветки. Числа v1 и v4 по разным схемам CV не сравнимы: v4 — честнее (v1 завышен смешением годов
и дублей). Сабмиты v1 и v4: мультикласс — 96.3% совпадающих меток; регрессия — корреляция 0.99 (RMSE между ними 6.9).
Какой лучше на public, покажет только сабмит на платформе (их делает P1).

**Ограничения и открытые вопросы**
- Сравнения с бейзлайном организаторов нет (его score виден только на платформе).
- Нужно от P1: `schemas.py` (сейчас локальные заменители по контракту из `CLAUDE.md`); семантика
  `Deadline.stage("fallback")` — сейчас используется, только если возвращает число секунд; когда появится
  `evaluator.py` — перейти на его сплиты (сейчас StratifiedKFold/KFold, shuffle, seed 42 — как у заглушки P4).
- Нужно от P2: `understand_task` → `TaskSpec`; `guess_spec` — только страховка.
- Схемы CV group/time по плану — зона `evaluator.py` (P1); здесь — своя схема fallback до его появления.
  Предложение P1: та же логика (`choose_cv`) или поле времени/групп в `TaskSpec` — по согласованию со всеми.
- Мультилейбл/мульти-регрессия — минимально (`run_multi`: по LightGBM на таргет).
