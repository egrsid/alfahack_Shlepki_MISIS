# Ветка `feature/agent-holdout` — защита агента от переобучения под CV (P4, @egrsid)

> Идея 4 из разбора «почему агент не улучшает модель». Ветка от `feature/agent-signals` (идеи 1–3).

## 1. Зачем

С быстрым скринингом агент проверяет за окно десятки гипотез. Правило «выигрыш > 1 · SE парных разностей» на 5
фолдах пропускает гипотезу без эффекта примерно в 19% случаев: за 30 гипотез — несколько ложных принятий, которые
выглядят как улучшение CV, но на test не работают. Данных, которых агент не видит, не было.

## 2. Что сделано

| Что | Где |
|---|---|
| `holdout_fold(data)` — скрытый фолд: при схеме «по периодам» — самый поздний период (ближе всего к test), иначе последний фолд; фолдов < 4 — нет | `agent_eval.py`, `RecipeEvaluator.holdout_fold` |
| решения агента (полная оценка и скрининг), CV в промптах, память экспериментов и анализ ошибок — без скрытого фолда (`_without_fold`, `_view`) | `agent.py` |
| в конце (`_holdout_check`, до доводки до 3 сидов): принятые шаги остаются, только если на скрытом фолде лучше эталона рецепта; не остался никто — результата агента нет, в файле fallback | `agent.py` |
| порог растёт с числом полных оценок: `accept_k` 1.0 → +0.25 каждые 10 → не выше 2.0; и выигрыш минимум на 60% фолдов (`min_fold_wins`, режим рецепта) | `agent.py` (`decide`, `_accept_cfg`) |
| скрининг: лучший по CV LightGBM fallback (а не самый весомый в рецепте), не больше 300 деревьев с пропорционально большим шагом — живой прогон показал, что прежний скрининг (`lightgbm_noperiod`, 1276 деревьев, без признаков сущности) был не быстрее полного рецепта | `agent_eval.ScreenEvaluator` |

## 3. Как проверить

```sh
LLM_DISABLED=1 .venv/bin/python -m pytest tests/ -q
set -a; source .env; set +a
.venv/bin/python tools/try_solution.py "Регрессия/task.md" --iters 60 --minutes 60   # в логе — «hidden fold»
```

Тесты (`tests/test_agent_holdout.py`): выбор скрытого фолда; доля выигранных фолдов; вид без скрытого фолда; рост
порога; итоговая проверка оставляет только обобщающиеся шаги и при пустом итоге возвращает fallback; настоящее
улучшение проходит скрытый фолд.

## 4. Ограничения

- Один скрытый фолд — шумная проверка: настоящее, но маленькое улучшение может не пройти. Это сознательный выбор:
  ложное принятие портит сабмит, пропущенное — оставляет fallback.
- Скрытый фолд участвует в итоговом сравнении с fallback в `solution.pick` (там все фолды): это уже не выбор из
  многих гипотез, а одно сравнение.
