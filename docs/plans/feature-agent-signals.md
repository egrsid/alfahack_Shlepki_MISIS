# Ветка `feature/agent-signals` — умные гипотезы: сигналы планировщику и фильтр бесполезных колонок (P4, @egrsid)

> Идея 3 из разбора «почему агент не улучшает модель». Ветка от `feature/agent-screening` (идеи 1–2).

## 1. Зачем

Живой прогон на public-регрессии: все гипотезы LLM — общие («погода × площадь», «возраст × погода»), одна дублирует
то, что fallback уже делает (частотное кодирование `facility_type`), log1p и квадраты отдельных колонок — бесполезны
деревьям, одна «гипотеза» добавляла 15+ колонок. Причина — LLM ничего не знает о сильном baseline: в режиме рецепта
её «текущее лучшее решение» — пустой `build_features`.

## 2. Что сделано

| Что | Где |
|---|---|
| `recipe_signals(recipe)` — текст для планировщика (≤ 1600 символов, один раз за запуск, ~10–30 с): модели и веса рецепта; схема CV (новый период в test / группы дублей) и что из этого следует; исключённые колонки; признаки сущности (ключ) — «не строить заново»; частотное кодирование, части дат, TF-IDF и удалённые колонки предобработки; важность признаков (gain LightGBM на матрице fallback, по исходным колонкам) и почти неиспользуемые; дрейф train→test (AUC классификатора «строка из test?» без колонки-периода и колонки, по которым он отличает test) | `agent_eval.py` |
| планировщик: раздел «Baseline facts … and signals» (профиль ужимается до 3400 символов — вызов в бюджете 4000 токенов); правило рецепта: ≤ 8 новых колонок, не строить то, что есть, сильные колонки — по важности, дрейфующие — через отношения/относительно группы; правило про доменные величины по смыслу колонок | `prompts_agent.py`, `agent.py` |
| `useless_new_columns`: новая числовая колонка — монотонное преобразование одной исходной (|ρ Спирмена| > 0.999 по строкам без пропусков) или копия другой новой → убирается с объяснением; все новые бесполезны → «rejected» (`useless:`) без оценки и без ремонта; больше 8 новых колонок → ошибка, кодер чинит с этой причиной | `agent.py` |
| заметки фильтра (что отброшено и почему) — в памяти экспериментов: LLM видит их при следующем планировании | `agent.py` |

## 3. Как проверить

```sh
LLM_DISABLED=1 .venv/bin/python -m pytest tests/ -q
set -a; source .env; set +a
.venv/bin/python tools/try_solution.py "Регрессия/task.md" --iters 30 --minutes 60   # в логе — «signals for the planner»
```

Тесты (`tests/test_agent_signals.py`): фильтр монотонных преобразований и копий, лимит колонок; сигналы описывают
рецепт, важности и дрейф; бесполезная гипотеза отклоняется без оценки и ремонта, раздел сигналов — в промпте; лишние
колонки уходят кодеру на ремонт с причиной; промпт с сигналами в бюджете.

## 4. Не сделано

- `DROP = [...]` (удаление дрейфующих колонок из матриц рецепта) — сигнал дрейфа уже есть, но удалять колонки агент
  пока не может. P3 проверял исключение погодных колонок на отложенном годе — в пределах шума.
- Сигналы только для режима рецепта (в боевом запуске он всегда, если fallback отдал контекст).
