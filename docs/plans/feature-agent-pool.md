# Ветка `feature/agent-pool` — агент как источник разнообразия для бленда (P4, @egrsid; правка P1 — с согласия)

> Идея 5 из разбора «почему агент не улучшает модель», в урезанном до сдачи виде. Ветка от `feature/agent-holdout`.

## 1. Зачем

На сильном fallback улучшения от признаков маленькие: поодиночке они не проходят порог шума и выбрасывались, хотя
(а) несколько таких вместе могут его пройти, (б) кандидат с другим набором признаков ошибается иначе и полезен
честному бленду, даже если сам не лучше.

## 2. Что сделано

| Что | Где |
|---|---|
| пул: оценённый полностью, но не принятый кандидат с выигрышем больше −шум (не «подозрительный скачок») — в пул, лучшие `pool_size` = 5; возвращается после принятых с `meta["pool_only"]` | `agent.py` (`_add_to_pool`, `result`) |
| `solution`: пул агента — только члены `ensemble.blend`, но не самостоятельные варианты записи (иначе обходили бы правило принятия и скрытый фолд агента) | `solution.py` (`improve(members=)`) |
| «почти принятые» (выигрыш > 0, но ниже порога): каждые 2 → гипотеза «объединить их» в начало очереди, кодер получает их диффы; сама гипотеза-объединение повторно не объединяется | `agent.py` (`_queue_combination`) |

## 3. Как проверить

```sh
LLM_DISABLED=1 .venv/bin/python -m pytest tests/test_agent_pool.py -q
```

## 4. Не сделано

- «Банк признаков» (10–30 колонок одним вызовом кодера и отбор по важности скрининговой модели) — скрининг (идея 2)
  и объединение «почти принятых» дают часть эффекта; полный банк — после сдачи.
- Члены бленда под дисбаланс классов (взвешенные XGBoost/CatBoost, undersampling-бэггинг) — зона P3, отдельно.
