# Ветка `feature/final-stage` — «зоопарк» моделей на рецепте fallback в простаивающее время (P1, @egrsid)

> Ветка от `feature/agent-tools` (v4). Шаги 0–3 общего плана: стенд замеров на отложенных копиях, финальный этап
> `final.py` (зоопарк), бленд под test (поздние периоды, новые уровни категорий), раскладка 3 часов. Сабмиты — отдельно.

## 1. Зачем

- **Время простаивает.** Живой прогон public-регрессии: fallback 456 с, агент остановился на T+36 мин (11 гипотез,
  0 принято), процесс закончился за 2190 с из 10 800. То, что двигает score на табличных задачах (другие модели,
  сиды, бленд), в оставшиеся ~2 часа никто не делал: `tuning` / `model_search` в режиме рецепта выключены,
  AutoML выключен.
- **Бленд собирался не всегда:** `solution.improve` строил `ensemble.blend`, только если агент или AutoML что-то
  вернули.

## 2. Что сделано

| Что | Где |
|---|---|
| `final.train`: новые модели на ТЕХ ЖЕ матрицах, фолдах, признаках сущности и исключениях, что у рецепта fallback (`fallback.cv_model`), — список по типу задачи + случайные варианты LightGBM/XGBoost, пока есть окно; модель, которая по оценке не успевает, пропускается; сбой модели — пропуск | `final.py` |
| регрессия: `xgb_log`, `lgbm_slow` (lr ×0.4), `lgbm_log_slow`, `cat_log` (лог — только при y ≥ 0; если рецепт уже с логом — «_raw»), `lgbm_et` (extra_trees), `xgb_d5` | `final.members` |
| классификация с метрикой по меткам при дисбалансе ≥ 3:1: `cat_sqrtbal` (CatBoost SqrtBalanced), `xgb_classw` (веса классов sqrt, `agent_eval.row_weights`), `lgbm_bal_reg` (balanced + регуляризация), `lgbm_bal_slow`; иначе — без весов классов | `final.members` |
| `final.bag`: ещё 2 сида для членов зоопарка с весом ≥ 0.1 в бленде | `final.py` |
| раскладка 3 часов: fallback → зоопарк A (`run_zoo_a`) до T+1:10 → агент до T+2:05, его доводка до сидов — до T+2:25 (`agent_deadline`) → зоопарк B (`run_zoo_b`: сиды весомых членов + ещё случайные варианты) до T+2:40 → 20 мин на финальный бленд, запись, проверку. Агент ушёл раньше — дальше сразу; без LLM зоопарк A — до T+2:05. `SOLUTION_FINAL_SECONDS` — потолок этапа (0 — выкл., так в тестах) | `solution.py` |
| бленд под test: схема «по периодам» — веса Caruana и отбор 16 кандидатов по поздней половине периодов (`ensemble.recent_rows`); строки test с уровнем категории, которого нет в train, — отдельный бленд по «стресс-строкам» OOF (уровень встречается только в своём фолде, `ensemble.new_level_rows`) | `ensemble.py` |
| `solution.pick` для схемы «по периодам» сравнивает только фолды поздних периодов (`ensemble.recent_folds`, `solution.on_folds`); **финальный бленд пишется, если по CV он хуже fallback не больше допуска** — 10% для схемы по периодам, 5% от (1 − score) / от ошибки для остальных (`BLEND_PREFERRED`, `within_tolerance`; осознанный риск — см. замеры) | `solution.py` |
| модели зоопарка — только члены бленда, не отдельные кандидаты на запись: из 14+ моделей одна по CV всегда «явно лучше» случайно | `solution.py` |
| lag-признаки сущности (последний известный таргет и давность) — члены `xgb_lag`, `lgbm_lag`, `xgb_log_lag` для схемы по периодам с сущностью | `final.py` |
| прогнозы строк test с новыми уровнями категорий берутся из бленда для новых уровней у ЛЮБОГО записываемого кандидата (`solution.with_new_levels`), даже если сам бленд по CV не пишется | `solution.py` |
| `solution.improve`: бленд собирается всегда; `report["blend"]` — веса для этапа B | `solution.py` |
| стенд `tools/holdout.py`: fallback (без записи) → зоопарк → бленды → сиды; таблица CV / отложенная часть (все строки и без новых уровней категорий); `meta.json` для `run_all.py` | `tools/holdout.py` |
| тесты | `tests/test_final.py`, `tests/test_ensemble_shift.py`; `SOLUTION_FINAL_SECONDS=0` по умолчанию в `conftest.py` |

## 3. Как проверить

```sh
LLM_DISABLED=1 .venv/bin/python -m pytest tests/ -q
.venv/bin/python tools/holdout.py reg_year5 cls_groups25
```

## 4. Замеры

**Копия public-регрессии** (`reg_year5`: train — годы 1–4, test — год 5 с ответами; в test 17.4% строк нового штата
State_11, которого в train нет). RMSE; «без новых» — строки, где все категории встречались в train. CV — то, что
видит решение (честное); «поздние» — среднее по фолдам поздних периодов (годы 3–4), так сравнивает `pick`.
fallback 147–205 с, зоопарк 14 моделей за 186–260 с (11–28 с на модель), сиды 52–59 с.

| кандидат | CV | CV поздние | год 5, без новых | год 5, все строки |
|---|---|---|---|---|
| fallback (в файле сейчас) | 41.84 | **36.84** | 30.30 | 49.68 |
| лучшие одиночные зоопарка: `xgb_d5` / `xgb_log` / `lgbm_log_slow` | 42.94 / 45.78 / 45.76 | 37.47 / 39.59 / 39.97 | **30.18** / 30.28 / 30.42 | 53.49 / 43.03 / 38.78 |
| бленд fallback (как было) | 42.13 | 37.26 | 30.25 | 49.55 |
| бленд fallback + зоопарк (как было) | 41.98 | 37.02 | 30.26 | 49.59 |
| + веса по поздним периодам | 42.34 | 37.68 | 29.95 | 48.76 |
| + бленд для новых уровней (3191 строка test, 254 стресс-строки OOF) | 42.34 | 37.68 | 29.95 | **42.72** |
| + сиды (`final.bag`) | 42.38 | 37.68 | **29.91** | **42.69** |

Выводы:
- через настоящий `ensemble.blend` зоопарк «как было» ничего не давал: отбор 16 кандидатов по CV всех фолдов
  отсекал лог-модели, лучшие на следующем годе; веса по поздним периодам и отбор по ним — −0.35 на годе 5;
- бленд для новых уровней: −7 RMSE по всем строкам года 5 (на новом штате XGBoost 53, лог-LightGBM / RF ~38–40);
- строгое правило записи («лучше больше шума») их не пропускало: CV по поздним фолдам у нового бленда хуже (37.68
  против 36.84) — при 4 годах честные веса фолда «год 4» подбираются по одному году 3, оценка шумная. Решение
  (25.10, «время рисковать»): для схемы «по периодам» финальный бленд пишется, если он не хуже fallback больше
  шума. На public-регрессии (годы 1–5 → 6) поздние фолды — годы 3–5. У public в test новых уровней нет.

С lag-членами (тот же стенд): финальный бленд CV поздних 38.95 (fallback 36.84, +5.7%) → год 5 **29.81** без новых
уровней (fallback 30.30), **41.60** по всем строкам (49.68). Отдельно: `xgb_lag` 30.24, `lgbm_lag` 30.51.

**Копия public-мультикласса** (`cls_groups25`: 25% групп дублей train в test). Macro F1, с порогом/весами классов.
fallback 574 с, зоопарк A 7 моделей за 1802 с (CatBoost 491 с), сиды 908 с.

| кандидат | CV | отложенная часть |
|---|---|---|
| fallback (XGBoost с весами классов, bag3) | **0.6428** | 0.6398 |
| бленд только моделей fallback | 0.6372 | **0.6500** |
| бленд fallback + зоопарк | 0.6347 | 0.6435 |
| + сиды | 0.6400 | 0.6466 |
| одиночные `cat_sqrtbal` / `xgb_classw` / `xgb_r1` (CatBoost fallback 0.5445) | 0.6245 / 0.6287 / 0.6231 | 0.6377 / 0.6353 / 0.6363 |

Выводы: бленды на отложенных данных лучше fallback (+0.007…0.010), а CV — наоборот: лучший кандидат fallback выбран
как максимум из многих по тем же OOF («проклятие победителя»). Зоопарк в мультиклассе к бленду почти ничего не
добавил (в пределах шума). Отсюда `BLEND_PREFERRED`.

**ZIP `37ab715` на 12 синтетических задачах** (`run_all.py`, без LLM, `SOLUTION_FINAL_SECONDS=61`): 12/12 корректный
файл; лучше прошлого — digits_weighted 0.9809 (0.979), multi_imbalance 0.8261 (0.824), small_wine 1.0 (0.979),
wide_logloss 0.2019 (0.204); хуже — reg_mae_en 44.93 (43.7): там строгое правило записало одиночную модель
зоопарка — исправлено (зоопарк только в бленде).

## 5. Ограничения

- Полный 3-часовой прогон на платформенном железе не делался — проверка будет сабмитом. Мультикласс: зоопарк A
  ~30 мин, сиды ~15 мин, зоопарк B до T+2:40.
- Правило записи бленда с допуском — осознанный риск: опирается на две отложенные копии (по одной на задачу).
- Члены зоопарка оцениваются по CV на фолдах fallback (ранняя остановка — по тому же фолду, как у fallback);
  решает честный бленд и правило записи `solution.pick`.
