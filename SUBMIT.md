## 2. Если архив надо пересобрать (например, файл повреждён)

```sh
git fetch origin
git checkout a0bbb79 && .venv/bin/python tools/make_zip.py --smoke   # → dist/solution_a0bbb79.zip — это v7
git checkout adf88cb && .venv/bin/python tools/make_zip.py --smoke   # → dist/solution_adf88cb.zip — это v8
git checkout main
```

Нужны только корневые модули и `requirements.txt` (список — `FILES` в `tools/make_zip.py`), ключи и данные не нужны.
`requirements.txt` не менять, файлы в архив не добавлять — платформа копирует только корневые `.py` и
`requirements.txt`.

## 4. Что изменилось и почему (кратко)

Подробно — `docs/plans/feature-blend-v7.md`. Замеры на копиях public-регрессии (train — годы 1–3 / 1–4, test — год
4 / 5 с ответами; RMSE по знакомым штатам, меньше — лучше):

| | год 4 | год 5 |
|---|---|---|
| fallback | 34.49 | 30.08 |
| бленд v6 | 33.48 | 29.73 |
| **бленд v7** | **32.26** | **29.64** |

В public-test 79% строк — здания, знакомые по train, а ~¾ квадрата ошибки дают новые здания: общие веса бленда
подбирались под новые, модели на истории зданий получали вес ~0. В v7 веса подбираются отдельно для знакомых и
новых сущностей (только регрессия с найденной сущностью; на классификации бленд — как в v6, плюс сиды моделей
fallback с весом в бленде).
